# 书稿 · 前期规划

长篇小说的前期规划与对账工具。**不碰正文**，只记账。

> 写书之前，把所有该想清楚的事想清楚，并保证它们之间不打架。

## 运行

### 方式一：双击（最简单）

根目录的 `书稿.html` 是单文件版本，双击就能用，不需要装任何东西。

- 数据存在浏览器 localStorage 里
- `file://` 下浏览器不给文件写入权限，所以「绑定本地文件」不可用
- 备份靠设置页的「导出 JSON」，建议每次写完导一份

### 方式二：本地服务（功能完整）

```bash
cd app
npm install
npm run dev      # 默认 http://localhost:5173
npm run test     # 单元测试（检查逻辑）
npm run build    # 构建
npm run build:single   # 打成单文件 → dist-single/index.html
```

localhost 版可以用「绑定本地文件」，每次改动自动写入你指定的 `.json`。

> 注意：必须用 `localhost`，不要用 `127.0.0.1`——两者是不同源，数据不互通。

### 开发提示

Vite 在 Windows 上偶尔会漏掉文件更新，导致浏览器拿到新旧混合的模块而白屏。遇到白屏先重启 `npm run dev`，再刷新页面。

## 已实现

- 章节表：章号、标题、概括、「这章结束时什么变了」、状态，行内编辑
- 实体：人物 / 钩子 / 道具 / 线，统一表结构
- 关联：埋 / 提 / 收 / 弃 / 出场 / 持有，挂到具体章节
- 四类检查：
  - C1 埋了没收
  - C2 收了没埋
  - C3 埋了太久没提
  - C4 线断了
- 欠债表：三分区（待还 / 待补 / 未标注）+ 「看了，不改」确认态
- 三态：有问题 / 已确认无问题 / 尚未录入，视觉上区分
- 设置：两个阈值可调
- 数据：localStorage 自动保存，可导出 JSON

## 设计约束（不可违反）

1. 0 问题 ≠ 0 数据
2. 判断型规则必须可关
3. 标签必须稀疏（一章 1–2 个）
4. 时间精度可变
5. 先呈现，后判断
6. 不碰正文
